# Swiggy Instamart Customer Intelligence & Support Copilot

## Project Overview

This capstone project uses **Python, SQL, machine learning, and a simple AI agent** to help an online grocery delivery business understand customers and handle support requests.

The project solves four problems:
1. Clean incorrect and duplicate order data.
2. Group customers and predict who may stop ordering (**customer churn / lapse prediction**).
3. Protect personal information and route customer support tickets.
4. Answer policy questions and handle refund requests using a rule-based tool workflow with an offline mock LLM.

## Tools Used

- **Python** and **pandas** — data cleaning and analysis
- **SQLite** — storing and querying order data
- **scikit-learn** — customer segmentation and lapse prediction
- **TF-IDF and cosine similarity** — finding relevant policy information
- **`mock_llm.py`** — offline mock language model (no paid API required)
- **VS Code and Jupyter Notebook** — development and project demonstration

## Project Parts

### Part A — Data Cleaning and SQL

- Cleaned customer, product, and order datasets.
- Stored the cleaned data in SQLite.
- Checked revenue using both Python and SQL.

**Results:** 1,200 customers, 40 products, 12,309 cleaned orders, and **₹29,98,668.80** in revenue from completed orders.

### Part B — Customer Segmentation and Churn Prediction

- Used **RFM analysis** (Recency, Frequency, Monetary value) to understand buying habits.
- Used **K-Means clustering** to group customers.
- Trained **Logistic Regression** and **Random Forest** models to predict customer lapse (churn).
- Prepared a retention list for customers who may stop ordering.

**Customer segments:**

| Segment | Customers |
|---|---:|
| Premium | 145 |
| Loyal | 419 |
| Regular | 469 |
| At-Risk | 167 |

**Model result:** The selected Random Forest model achieved approximately **72% test accuracy** and **0.65 F1-score for the lapsed class**.

### Part C — Support Ticket Privacy and Routing

- Reviewed **164 support tickets**.
- Redacted email addresses, phone numbers, and order IDs.
- Classified tickets into support categories using the offline mock LLM.
- Assigned tickets to suitable support queues and priorities.

**Result:** 278 personal-information items were redacted. The zero-shot classification test achieved **85.71% accuracy** in the project evaluation.

### Part D — Policy Q&A and Refund Agent

- Loaded delivery, refund, payment, privacy, and escalation policies.
- Built a simple **RAG (Retrieval-Augmented Generation)** workflow to find relevant policy text before answering questions.
- Built a refund agent that checks order details, policy, and refund eligibility.
- Added safeguards for missing orders, duplicate refunds, token limits, timeouts, and human escalation.

**Policy evaluation:** 12/12 supported questions passed the recorded retrieval and fact checks; 2/2 unsupported questions used the fallback response.

**Refund rules demonstrated:** Eligible completed orders delivered after 45 minutes may receive a refund. Eligible refunds above **₹1,000** are escalated for human approval instead of being automatically issued.

## How to Run the Project

1. Download or clone this repository and open its folder in **VS Code**.
2. Create and activate a Python virtual environment if needed.
3. Install the required packages:

   ```powershell
   python -m pip install -r requirements.txt
   python -m pip install ipykernel
   ```

4. Open **`Swiggy_Instamart_Capstone.ipynb`** in VS Code.
5. Select your project's Python environment as the Jupyter kernel.
6. Choose **Restart Kernel → Run All** to view the project demonstration.

The notebook reads files generated by the project scripts. Keep the repository folders together. The full implementation is in the `part_a/`, `part_b/`, `part_c/`, and `part_d/` Python scripts.
